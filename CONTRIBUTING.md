# Contributing to Xentrolance Technical Labs

Thank you for your interest in contributing. We welcome high-quality contributions that improve security, reliability, and developer experience across our public repositories.

## Before You Start

1. Read our [Code of Conduct](./CODE_OF_CONDUCT.md).
2. Check existing issues and pull requests to avoid duplicates.
3. For larger changes, open an issue first so we can align on approach.

## How to Contribute

### Report bugs

Open an issue with:

- Clear title and description
- Steps to reproduce
- Expected vs actual behavior
- Environment details (OS, runtime, versions)
- Logs or screenshots when relevant

### Suggest features

Describe the problem, proposed solution, and any alternatives considered. Prefer concrete use cases over abstract ideas.

### Submit code

1. Fork the repository
2. Create a focused branch (`feat/…`, `fix/…`, `docs/…`)
3. Follow existing code style and project conventions
4. Add or update tests where applicable
5. Update documentation for user-facing changes
6. Open a pull request with a clear summary and test plan

## Engineering Expectations

- Prefer small, reviewable pull requests
- Do not commit secrets, credentials, or private keys
- Keep CI green — tests and lint must pass
- Security-sensitive changes should include threat notes in the PR description

## Security Issues

Do **not** open a public issue for vulnerabilities. Follow our [Security Policy](./SECURITY.md).
